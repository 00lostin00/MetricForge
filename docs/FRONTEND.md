# MetricForge 工作台操作说明

工作台把真实任务接口接到一个中文页面上。任务、验证和交付由 Python 后台完成，浏览器负责提交、轮询、展示和导出。默认运行使用虚构数据与固定 Replay 策略。

## 启动与入口

```bash
uv sync --frozen --all-extras
uv run --frozen --all-extras uvicorn metricforge.api:app --host 127.0.0.1 --port 8014
```

访问 http://127.0.0.1:8014/。Windows 可以运行 `./start.ps1 -Port 8014`。工作台、脚本、样式与 Logo 均来自本地服务，不需要安装 Node。API 仍可在 `/docs` 独立使用。

## 一次完整演示

1. 保持默认“收入同比”。左侧口径明确：本年与上年营业收入差额除以上年营业收入，金额单位先归一化。
2. 编辑研发需求。需求长度为 4 至 800 字符。Replay 采用预设候选策略，修改需求文字不会改变它的表达式生成行为；LLM 模式才会由模型根据需求提出候选。
3. 使用 Replay，展开验证参数。默认种子为 `20261012`，额外生成 32 个样本。固定样本始终参与验证；额外样本范围为 0 至 128，种子必须是 0 至 `2147483647` 的整数。
4. 点击“开始验证与交付”。按钮在任务运行时禁用，避免误点重复提交。每次提交使用新的幂等标识。
5. 收入同比的第一版使用本年收入作分母。它能通过 AST 编译，但参考验证会发现数值不一致。工作台显示两项检查的区别。
6. 查看反例缩减。工具在最多 80 次尝试内简化输入，同时保留原来的失败类别与状态。若不能继续简化，页面会明确显示未进一步缩减。
7. 第二版换成上年收入作分母，重新验证全部样本。只有全部通过，才冻结验收版本并交付图表。
8. 宽屏中两版公式并排展示，琥珀色标记保留失败证据的候选，绿色标记冻结后的验收版本。每版可复制公式，展开修订理由与诊断；完整失败列表保存在交付 JSON 中。
9. 展开底部“执行轨迹”，可以看到工具名、执行顺序、输入及返回摘要。轨迹默认收起，顶部导航可以直接打开。
10. 打开 HTML 报告或下载 JSON / SVG。报告保留契约、两版表达式、参考通过数量、反例与虚构样本图表。

“净利率”和“现金转化率”也有各自的预设错误与修订表达式。两项均调用相同真实编译器、参考验证器与缩减工具，不是前端写死的成功结果。

## 看懂结果

| 内容 | 解释 |
| --- | --- |
| 验收通过 | 最终候选在本次固定与种子生成样本上通过重新验证 |
| 未通过验收 | Agent 没有完成有效候选验收；保留轨迹及可用候选 |
| AST 编译通过 | 语法、白名单、预算与量纲满足编译规则；不保证业务语义正确 |
| 验证 X / Y | 该候选与独立参考程序一致的样本数 / 本次总样本数 |
| 工具调用 | 本次实际调用数量，上限为 20 |
| 后台耗时 | 后端计时的本次运行耗时，不包含页面等待与下载时间 |
| 图表无数值 | 缺失字段、零或非正基数、缺期、口径不一致等状态；不会补为零 |

工作台数值只反映本次运行，不用于推断泛化效果。图表从前 7 个演示样本生成，涵盖有效值、负值和不支持状态；它不是实时行情或公司研究结论。

## 最近任务与刷新

最近 10 项任务的 ID、需求、参数和状态保存在当前浏览器 `localStorage`，标为本地历史。选择一项会向后台重新获取任务及事件，而不是只显示一张缓存结果。

清空历史只删除浏览器记录，不删除后台 SQLite 或交付文件。当前会话中可点击“撤销”恢复清空前的记录；新任务记录与恢复记录去重合并。后台更换状态目录或删除任务后，原本地记录可能返回“未找到任务”；页面会给出说明。浏览器不允许本地存储时，历史仍可在当前会话里使用。

地址栏保存所选指标、当前任务 ID 和轨迹展开状态。复制当前页面地址可以在同一后台服务上恢复任务；地址不包含需求正文。手动编辑但尚未提交的需求在离开页面时会提示，提交成功后解除提示。

运行时可点击“暂停刷新”。它只停止轮询；已经提交的后台任务不会被取消。点击“继续刷新”重新连接当前任务。网络错误会自动重试两次，仍然失败时允许手动继续刷新。后台服务重启会把未完成任务标为中断，此时请重新提交。

## LLM 模式

先在服务端配置 `OPENAI_API_KEY` 和 `METRICFORGE_MODEL`，重启服务后页面才会开放 LLM 选项。需要安装 `llm` 可选依赖；上述 `--all-extras` 安装命令已包含它。项目不会自动加载 `.env`。

模型通过 6 类受约束工具提出、验证和修订候选；没有任意代码执行接口。实际模型调用可能产生费用，并会将需求发送给模型提供方。页面不显示密钥，`/v1/capabilities` 只返回是否配置。模型效果必须实测，Replay 的通过记录不能当作模型通过率。

## 接口与文件

| 页面操作 | 接口 |
| --- | --- |
| 读取指标契约与配置状态 | `GET /v1/capabilities` |
| 提交任务 | `POST /v1/jobs`，请求头 `Idempotency-Key` |
| 获取状态与结果 | `GET /v1/jobs/{run_id}` |
| 获取执行轨迹 | `GET /v1/jobs/{run_id}/events` |
| 报告、JSON、SVG | `GET /v1/jobs/{run_id}/artifacts/{filename}` |

页面不把需求或模型返回值拼接为 HTML；动态内容使用 `textContent` 和 DOM 节点。报告使用 HTML 转义，图表使用 SVG 文本转义。静态路由只挂载 Python 包中的 `web` 目录，不对外提供数据库、配置文件或整个项目目录。

## 故障处理

- **服务未连接**：检查启动日志、端口和进程；重新打开工作台地址。不要直接双击 HTML 文件，因为界面需要本地 API。
- **队列已满**：后台最多有 6 个在途任务，等待运行结束后再提交。
- **LLM 未完成验收**：检查服务端密钥、模型是否支持工具调用以及模型配置；展开工具轨迹，再查看交付错误。
- **图表不存在**：没有验收表达式时不会交付图表。报告和 JSON 仍保留可用诊断。
- **导出 Logo 或图表不显示**：服务对 SVG 明确返回 `image/svg+xml`，避免 Windows MIME 注册表产生非标准类型。检查是否打开了旧服务版本。
- **修改数据目录后任务消失**：本地历史与服务端 SQLite 是两份状态；原记录不会自动迁移到新目录。

## 实现位置与验证

`src/metricforge/web/` 包含静态页面、脚本与 SVG Logo。`style.css` 统一颜色、字号、表单控件和状态；`console.css` 仅定义工作区布局与专属组件，不重复覆盖基础颜色或用 `!important` 压低字号。`api.py` 提供入口与同源静态资源。`tests/test_workbench.py` 验证静态资源、配置状态不泄露密钥，以及三个指标的真实提交、状态、反例、事件、报告和 SVG MIME。

```bash
uv run --frozen --all-extras pytest
uv run --frozen --all-extras ruff check .
```

桌面布局采用 320px 契约输入列与明亮候选工作区。两版公式在足够宽的屏幕上并排对照，中等屏幕转为纵向；执行轨迹收纳在底部展开面板。窄屏按输入、历史、结果、轨迹顺序呈现。图表保留至少 840px 的画布宽度，数据行与数值为 14px，不压缩成小字；可以在图表容器内独立横向滑动，键盘聚焦图表后也可使用方向键查看全部数值与状态。正文与表单主要为 14 至 16px，辅助信息最低 12px，操作控件至少 44px 高。键盘焦点可见、状态变化可播报，减少动态效果设置会停止加载旋转。

截图位于 `docs/screenshots/workbench.png`，从真实运行任务后的页面获取。

浏览器验收使用实际 Chrome，覆盖三个指标完整流程、历史记录跨刷新恢复、JSON 下载，以及桌面和 390px 窄屏布局。记录中没有 JavaScript 错误或页面横向溢出。另用浏览器模拟 429 响应检查错误提示与重新提交；该项不是后端吞吐压测。详情见[浏览器验证记录](validation/browser-workbench.json)。
